# @tableslayer/stage rendering architecture

> **Freshness**: last verified 2026-11-02 (Threlte 8.6, Three 0.186, postprocessing 6.39).
> Anchor files at the bottom — if one is missing/renamed, the code wins; update this skill.
> Deeper current docs: `docs/grid-system-architecture.md` (grid math), `docs/stage-performance-guide.md` (perf workflow).

## Big picture

- `Stage.svelte` (`packages/stage/src/lib/components/Stage/components/Stage/Stage.svelte`) is the public entry: creates a custom `WebGLRenderer` (`antialias: false` — everything is textured quads AA'd in-texture; MSAA would be wasted), renders `<Canvas renderMode="always">` (continuous loop — animated shaders/weather need it), and mounts `Scene.svelte`.
- **Idle frame pacing** (`helpers/framePacing.ts`): the loop always ticks (tasks run, `uTime` advances), but Scene's render task skips GPU work while idle — `IDLE_FRAME_RATE` per tier (`high: null` = uncapped, medium 30, low 20). Skipping a frame without GL calls keeps the previous image on the canvas. Scene puts the pacer in context `'framePacer'`; anything that marks activity gets full rate for `ACTIVE_WINDOW_MS`: props-root/cursors/measurement changes, window pointer/wheel/key input, map load, resize. **Ambient pacing**: a layer whose animation merely loops (an animated AoE area) calls `framePacer.markAmbient()` each frame instead of `markActive()`; the render task passes `AMBIENT_FRAME_RATE[tier]` (high 60, medium 30, low 24) as the cap while an ambient mark is fresh (`AMBIENT_WINDOW_MS`), so one Spirit Guardians area no longer holds the stage at uncapped fps. A layer with a transient animation that must stay smooth (a fading template, a cast, the MeasurementManager fade) calls `getContext<FramePacer>('framePacer')?.markActive()` from its task (MeasurementManager fade, CursorLayer while cursors exist). Async texture updates while idle appear on the next idle frame (≤ 50 ms).
- `Scene.svelte` is the heart: single `T.OrthographicCamera`; **pan/zoom is applied to a wrapping `T.Object3D` (`props.scene.offset`/`zoom`), not the camera**. Inside it, a **`mapAnchor` node always carries the uniform map transform** (`position = map.offset`, `rotation = map.rotation`, `scale = map.zoom`); `MapLayer`'s inner node only scales the unit plane to the image size.
- **MapDefined anchoring**: grid/annotation/light/marker/measurement layers live in an `anchoredLayers` snippet mounted **inside `mapAnchor`** when `gridMode === MapDefined` (and `mapSize` is loaded) and at scene level in FillSpace. Anchored layers receive a **synthetic map-space `DisplayProps`** (`anchoredDisplay` via `getMapSpaceDisplay`: resolution = mapSize px, size = fixedGridCount × spacing "inches") so all their display-space math computes in map pixels unchanged, plus `localScale` (= map.zoom) to convert screen-px style values to local px. Marker/light positions are center-relative **map pixels** in MapDefined, display pixels in FillSpace; conversion contract lives in `helpers/mapSpace.ts` (THREE-free, exported — apps/web shares it).
- Two distinct "layer" enums in `Scene/types.ts` — do not confuse them:
  - `SceneLayerOrder` — Three.js `renderOrder` (Background 0 → Map 10 → Fog 20 → … → Grid 50 → … → TvViewport 95 → Cursor 100).
  - `SceneLayer` — Three.js camera-layer masks: `Main = 0` (gets postprocessing), `Overlay = 1` (grid/measurement/cursor — deliberately skips bloom/LUT), `Input = 2` (invisible raycast targets).
- **Two-pass render loop** (custom `useTask` in Scene.svelte; Threlte `autoRender` is disabled, `renderer.autoClear = false`): pass 1 renders `Main` through the `postprocessing` EffectComposer (Bloom, ChromaticAberration, Vignette, LUT3D, ToneMapping); pass 2 renders `Overlay` directly. If all effects are zero-strength (`getActiveEffects`), the composer is **bypassed entirely** — a key perf path. The composer is disposed and rebuilt whenever `props.postProcessing` changes.
- Offscreen targets: WeatherLayer renders particles into its own `WebGLRenderTarget`; `DrawingMaterial` (fog-of-war + annotation painting) uses **double-buffered ping-pong render targets**; `generateThumbnail` swaps a temp scene/camera into the composer and reads back via `OffscreenCanvas`.
- **Mask readback is async and lazy.** `DrawingMaterial.toPng/toRLE` use `renderer.readRenderTargetPixelsAsync` (three issues `readPixels` into a PBO before its first await, so the snapshot is taken at call time; callers re-check `isDrawing()` after awaiting). `onFogUpdate(getBlob)` / `onAnnotationUpdate(layerId, getBlob, pos)` receive a **thunk** — call it only if you need the PNG; never pass an eager `toPng()` (that was a full-res readback + PNG encode per stroke the editor discarded). RLE encode/decode live in `@tableslayer/ui` `utils/rle.ts`; output format is persisted, so changes must stay byte-identical (`rle.test.ts` pins it against the legacy encoder).
- **Map images decode off the main thread**: `ImageDataSource` uses `fetch` + `createImageBitmap({ imageOrientation: 'flipY', colorSpaceConversion: 'default' })` with `texture.flipY = false` (WebGL ignores UNPACK_FLIP_Y for ImageBitmap; three's `ImageBitmapLoader` is avoided because it forces `colorSpaceConversion: 'none'`). `dispose()` closes the bitmap, so detach `material.map` before disposing a source whose mesh stays mounted. Falls back to `TextureLoader` without `createImageBitmap`.
- **Fog.frag**: the feathered mask (mip loop) and base mask are computed once in `main()` and passed to the per-layer `mask()`; only the edge noise is per-layer. Don't move texture work back into per-layer functions.
- **Polygon fog rooms** (`props.fogOfWar.rooms`, `helpers/fogRooms.ts` — THREE-free, shared with apps/web): committed rooms + the in-progress draft are rasterized into a map-sized `CanvasTexture` in `FogOfWarMaterial` — enabled rooms in the GREEN channel, toggled-off rooms in RED — and composited in `Fog.frag` as `max(enabled, base * (1 - disabled))`: erase strokes never cut into enabled rooms, a toggled-off room actively reveals its interior through the base mask, and an enclosing enabled room still wins (nesting). Room points are normalized [0-1] mask-UV (v up; canvas draws at `(1-v)*h`, CanvasTexture flipY un-flips). Data out via `Callbacks.onFogRoomAdd/onFogRoomToggle/onFogRoomDelete` (hit-tests pick the smallest containing room, enabled or not); commit via Enter (consumer's job through `StageExports.fogOfWar.commitPolygon/cancelPolygon/polygonPointCount`), double-click/double-tap, or clicking the first vertex. Toggle = right-click or touch double-tap with ANY tool/layer active, in DM mode AND on the Player-mode playfield (`LayerInput.isContextMenuActive` bypasses the isActive gate for contextmenu; `LayerInput.onDoubleTap` is an always-on touch detector). Marker precedence: consumers defer the right-click toggle one tick so a marker context menu wins; on touch, MarkerLayer stamps `stageContext.markerClaimAt` on marker-hitting pointer-downs and the fog layer's double-tap defers 120ms and yields to recent claims. Delete = Delete/Backspace while hovering (`deleteRoomAtCursor`) or touch press-and-hold — both polygon-tool-gated, so effectively editor-only (Shift+right-click also works, but Firefox forces its native menu on Shift+right-click regardless of preventDefault — never make that the only path). stageKeyCommands' Shift-deselect exempts the polygon tool (it ignores Shift/Ctrl-modified clicks itself). Preview/outlines are triangle ribbons + disc vertices (`FogRoomLine/Disc` shaders, fwidth-feathered — LineBasicMaterial linewidth is unsupported) built at constant ON-SCREEN thickness by dividing by `mapZoom * sceneZoom` (a fixed texture-px width goes sub-pixel and aliases when zoomed out); the cursor acts as the provisional last vertex so the draft always reads as a closed polygon. The draft deliberately survives `isActive` toggles (Ctrl pan) and resets on tool/map change.

## Props and control flow

- One flat `StageProps` object (`Stage/components/Stage/types.ts`) with a sub-object per layer, passed down whole; layers take their slice.
- **The stage never mutates props.** Data flows out through the `Callbacks` interface (`onSceneUpdate`, `onFogUpdate`, marker/light/measurement callbacks), provided via `setContext('callbacks', …)`; the parent writes new values back into its `$state` stageProps. Pan/zoom round-trips through this loop.
- Imperative API: `StageExports` — parent does `bind:this={stage}` and calls e.g. `stage.fogOfWar.toRLE()`. These delegate Stage → Scene → layer → material with `?.` at every hop.
- `stageContext` (context `'stage'`) carries reactive `mode`, `performanceTier`, hovered/pinned marker ids.
- Input (pan/zoom/rotate gestures, wheel, keyboard) is the **parent's** job via the exported `PointerInputManager` — Stage itself doesn't bind wheel/keys.

## Shaders

- GLSL lives in `packages/stage/src/lib/components/Stage/shaders/*.frag|.vert`, imported as strings with Vite `?raw`. Exception: the light shader is inline TS (`LightLayer/lightShader.ts`, uses `#include <clipping_planes_*>`). `AnnotationEffects.frag` is the 1600-line monster (22 effects: 1–8 hand-made, 9–22 ported from `AoeTemplate.frag` and fed from the mask by `portedEffect()`, which derives grid-cell coordinates from `uCellSize` and an edge distance from one mip level ≈ one cell) — but **the effect is a compile-time `EFFECT_TYPE` define** (`AnnotationMaterial` sets `defines.EFFECT_TYPE`, each effect's functions sit in `#if EFFECT_TYPE == n` blocks, `main()` dispatches with `#if/#elif`), so a program only contains its own effect. Never move effect selection back into a uniform: the all-in-one program took ~90 s to link on Windows, where both Chrome and Firefox run WebGL through ANGLE → D3D11 → the FXC HLSL compiler, which inlines/unrolls everything (Chrome's GPU watchdog then killed the process → context-loss loop). Same rule for any new big shader: branch on defines, keep loop bounds literal.
- **Shader precompile**: `AnnotationMaterial` links its program via `renderer.compileAsync` (`KHR_parallel_shader_compile`) with `material.visible = false` until ready, so a slow link never stalls the frame loop. three keys programs on (among other things) `renderer.clippingPlanes.length`, the defines, and whether the output is a render target (`outputColorSpace` param) — so the probe compile binds a 1×1 render target when the layer will render through the composer (`stageContext.mainPassUsesComposer`, computed by `helpers/postProcessing.ts`). If a material still links twice, diff the two program sources (`#define` prefix) — that's how the target/plane-count keys were found. The F9 perf overlay shows `Programs` (`renderer.info.programs.length`) to spot thrash. `EffectPreviewScene` (radial menu / DrawingSliders effect thumbnails) is one Threlte `<Canvas>` = one WebGL context per preview: it uses the same `compileAsync` gate and **releases its context on unmount** (`WEBGL_lose_context.loseContext()` after Threlte's dispose) — browsers cap live contexts (Chrome 16) and evict the oldest, i.e. the stage.
- Uniform idiom: create uniforms once at material construction; update in `$effect` with **in-place mutation** (`uniforms.uColor.value.set(...)`, `.copy(...)`) — never allocate new objects per frame. Time-driven uniforms advance in `useTask((delta) => { uniforms.uTime.value += delta })`. Dispose materials in `onDestroy`.
- The JS grid-snapping math in `helpers/grid.ts` is a **hand-ported mirror of the shader's `getHex`** (and compensates for the shader's `lineThickness/4.0` visual offset). If you change `GridShader.frag` grid math, change `helpers/grid.ts` to match, and vice versa.

## Gotchas (the expensive ones)

- **`$state.raw()` for Three objects** (`$state.raw(new THREE.Mesh())`) — Svelte 5 proxies break Three's internals. Recurring pattern in FogOfWarLayer, WeatherLayer.
- **Y-flips everywhere**: render-target readback is vertically flipped — `toPng` un-flips via canvas transform; `toRLE`/`fromRLE` flip rows manually (`height-1-y`) and pack **alpha channel only**. NDC→pixel conversions flip y (`-v.y*0.5+0.5`). The weather particle camera is intentionally upside-down (`rotation.x = Math.PI`).
- **Brush sizes are in grid units**, converted to texture pixels via `getGridCellSize` (fog additionally divides by map zoom; annotation uses the synthetic map-space display in MapDefined — the two formulas agree under the locked zoom), then **halved** (shaders treat `uBrushSize` as a radius).
- **Resize must happen in the render task, not `$effect`** — `needsResize` flag pattern in Scene.svelte; the size-mismatch check doesn't work in effects.
- **Effects must key off prop VALUES, not sub-object identity.** apps/web replaces the whole stageProps ROOT on every remote doc change — structural sharing preserves identity for unchanged subtrees, but any effect whose dependency chain reaches the root signal still re-fires per received update. Template-expression props (`strokeColor={props.marker.shape.strokeColor}`) carry the root in their chain, so a child effect reading such a prop directly re-runs per remote pan step even though the value never changed. Only `$derived` cuts the chain (it re-propagates only when its VALUE changes). Three past incidents: setSize + autoFit refit per update (Scene.svelte `resizedForMapUrl` guard), full EffectComposer rebuild per update (`lastPostProcessingKey` guard), and per-marker canvas redraw + gaussian shadow blur + texture upload per update (~30ms/marker; MarkerToken routes every style prop through `$derived`). When adding an expensive effect, route each input through `$derived` or a last-value comparison.
- DPR is capped by `props.display.maxPixelRatio` (default 2) for weak GPUs.
- **Performance tiers**: `PerformanceTier = 'high'|'medium'|'low'` with the knob table `PERFORMANCE_TIER_SETTINGS` in `Stage/components/Stage/types.ts` (fog layer count/octave cap, weather resolution+particle scale, `forcePostProcessingOff` on low). The consumer picks the tier — Stage never auto-detects. Shaders also receive `uPerformanceTier`. Tier changes apply live.
- **Clipping planes**: two stores in `helpers/clippingPlaneStore.svelte.ts` — display bounds (on the renderer) vs map bounds (on weather/light materials so effects stop at map edges). **Never set `renderer.clippingPlanes = []`** — always four planes (`noClipPlanes()` pushes them to ±1e9): three substitutes the count into `NUM_CLIPPING_PLANES` and keys the program cache on it, so `[]` would relink every material and give shaders a zero-length `uClippingPlanes[]`. `Stage.svelte` sets the four planes at renderer creation; `generateThumbnail` and `annotationSpaceConversion` use `noClipPlanes()`. In **DM + MapDefined** the display-bounds store is "disabled" the same way so the whole map is visible; `TvViewportLayer` draws the playfield rectangle + dim mask instead. Player mode keeps clipping.
- **MapDefined grid cells are always square**: the quad IS the map; the synthetic map-space display has uniform pixel pitch, so `gridSpacing = uSpacing_in/pixelPitch` yields the per-axis-average square cell and the grid is centered on the map (count/aspect mismatch = edge misfit, not rectangles). Mirrored in `helpers/grid.ts` (`getGridOrigin` centers; `snapToGrid` takes an optional `localScale` for the `t/4` offset compensation). The count describes the map image (X along the image's width, like the `name_WxH` filename convention) and is invariant under rotation. Grid lines are analytically AA'd inside `squareGrid`/`hexGrid` via `fwidth()` with the half-width floored at one device pixel — sub-pixel hard bands alias into patchy moiré/phase-dependent brightness.
- **Legacy annotation conversion**: persisted RLE masks embed 8-byte width/height; in MapDefined, a mask at the real display resolution is legacy display-space data and gets GPU re-projected into the map-sized texture (`helpers/annotationSpaceConversion.ts` + `AnnotationMaterial`'s `conversion` prop), then persisted once via the normal `onAnnotationUpdate` flow.
- `scene.fit()` in DM + MapDefined frames the map ∪ TV rect (5% margin) instead of the display bounds; `getMarkerScreenPosition`/`getMarkerSizeInScreenSpace` apply the map transform in MapDefined.
- MapLayer disposes the old data source and `material.map` before loading a new one; video URLs keep query params (cache-busting) while image URLs strip them. Data sources are pluggable (`MapLayer/dataSources/` — Image, Video, Gif — each with `.dispose()`).
- Desktop Ctrl-drag pans the whole scene (map, grid and tokens together). Shift-drag is reserved for editor token selection, and never pans the map. In DM + MapDefined, Alt-drag (Alt held at press) moves the TV viewport rectangle by panning the map the opposite way (`altPansView` on the stage context); LayerInput yields Ctrl/Meta mouse-downs, and Alt too in that mode, to view controls. Touch map/scene gestures remain separate.
- `marker.selectedIds` and `marker.dropTargetId` are optional local selection/drop presentation state; consumers must keep it out of shared documents. `markers.hitTest` and `markers.inRectangle` accept viewport client coordinates, project through the current map and scene transforms, and exclude non-interactable tokens. The editor captures Shift mouse gestures before layer handlers; Shift-click toggles and Shift-drag adds token centers in the rectangle.
- `markers.clientToPosition(point, requireOnMap)` inverts the live orthographic camera, scene offset/zoom and (in MapDefined) map offset/rotation/zoom. `markers.viewportCenter()` supplies a paste fallback; `markers.snapPosition()` applies the renderer's grid math once to the group anchor. Public `getGridCellSize` and `snapToGrid` exports let consumers reuse existing grid calculations.
- Touch input debounces 50ms to disambiguate draw vs pinch-zoom (`LayerInput.svelte`). Touch move/end are deliberately NOT gated on `(any-pointer: coarse)`: touchscreen TVs often report a fine pointer, and gating stranded drags mid-gesture. A tap released inside the 50 ms wait still fires press then release, with the release one tick later so layers that defer their press (the marker-claim `setTimeout(0)` in Light/AoE) see them in order. `touchcancel` ends any in-progress gesture via `onMouseUp(e, null)`, so every layer's mouse-up must accept null coords.
- Lights are selectable and draggable in both the Light tool and the no-tool state (`LightLayer` is active for `None` too); in `None` a light click defers one tick and yields to a marker claim (`markerClaimAt`). Consumers may pass `selectedLightIds` (a `<Stage>` prop, copied into the `'stage'` context) to draw several lights as selected; without it the layer highlights the light it last picked. `StageExports.lights.hitTest/inRectangle` take marker-space points, like the AoE ones. The editor's Delete/Backspace removes everything selected (tokens, lights, AoEs) with no tool active.
- Annotation layers with visual effects render on `SceneLayer.Main` (get postprocessing); plain-color layers render on `Overlay`.
- **Annotation effect catalog**: `helpers/annotationEffects.ts` (`ANNOTATION_EFFECTS`, `ANNOTATION_EFFECT_CATEGORIES`, `annotationEffectsInCategory`) holds label, hint, category and layer color for every effect; `DrawingSliders` (category tabs), `EffectPreviewScene` colors and the TV Draw ring all read it. `AnnotationEffect` values are persisted (`annotations.effect_type`): append, never renumber. Pickers show one category of `EffectPreview`s at a time (each is a WebGL context).
- **Annotation eraser**: `annotations.tool = 'erase'` paints with `DrawMode.Erase`; with `eraseLayerIds` one stroke erases all those (visible) layers, otherwise the active layer. `onAnnotationUpdate` fires once per touched layer; `StageExports.annotations.toRLE(layerId?)` reads a specific layer. `StageExports.scene.gridCellScreenSize()` gives one grid cell in CSS px (brush previews).

## Tokens, selection and combat state

- **Selection is not in props.** Consumers pass `selectedMarkerIds`, `dropTargetMarkerId` and `activeTurnMarkerId` as `<Stage>` component props (`StageInteractionProps`); `Stage.svelte` copies them into the `'stage'` context, and MarkerLayer reads them from there. Keeping them out of the `props` root means a click does not invalidate every effect chained to `props` (see the effects gotcha above). `marker.selectedIds`/`dropTargetId` remain as a fallback.
- **Token raster never encodes selection, hover or turn state.** `MarkerToken` draws image/shape/label into a 512px `CanvasTexture` that is reused across redraws and recreated only when the raster size changes, since three allocates immutable GPU storage on first upload (design space stays 1024 via `setTransform`; shadow blur is scaled by hand). Selection, hover and active-turn are separate ring meshes with shared materials (`helpers/tokenRasterCache.ts`: shared quad geometry, `ImageBitmap` LRU (128 URLs, evicted bitmaps are dropped, never `close()`d — a token may be about to draw it) via `loadTokenImage`, CSS colour cache invalidated by a theme `MutationObserver`; colours are normalised to `rgb()` through a 1px canvas because `THREE.Color` can't parse the oklch theme tokens). The active-turn pulse is one `useTask` with `running: () => isActiveTurn` (a `useTask` cannot sit inside `{#if}`).
- **Drag threshold**: a press becomes a drag only after 3px (mouse) / 8px (touch); a stationary click never calls `onMarkerMoved`. Pressing a token that belongs to a ≥2 selection starts a group drag that reports through `onMarkersMoved(moves)` (falls back to per-marker `onMarkerMoved`); the gesture end (mouseup, window blur, layer reset/unmount) fires `onMarkersMoveEnd({ ids, cancelled })` — consumers close their undo group there, never on an idle timer. Escape mid-drag restores start positions, calls `preventDefault` and reports `cancelled: true`. A press on an already selected token (or light) reports `onMarkerSelected` (`onLightSelected`) on release and only if the press did not become a drag, so dragging a selection never changes it; a press on an unselected one still reports on press. The editor relies on this to cycle through asset groups on click. While a press is still below the threshold, `markerState.tooltipSuppressed` is true so the player tooltip doesn't flash.
- **Conditions**: `Marker.conditions` (`MarkerCondition { id, label?, color?, value?, dmOnly? }`). Catalog and pure helpers live in `helpers/markerConditions.ts` (`MARKER_CONDITIONS`, `MARKER_CONDITION_ORDER`, `MARKER_CONDITION_CATEGORIES`, `conditionIdsInCategory`, `resolveCondition`, `toggleCondition`, `sortConditions`), exported for apps/web. Each condition has a `category` (eight plus custom, at most 8 conditions each so a category fits one radial ring); catalog order is display order and follows the categories. Icons live in apps/web (`utils/conditionIcons.ts`), so the stage stays free of icon dependencies. `MarkerConditionBadges` renders inside the token's scaled group; `dead` dims the token and overlays a skull. Consumers filter `dmOnly` conditions out of player props.

## AoE templates

- `AoeTemplateLayer` (`components/AoeTemplateLayer/`) renders spell templates (circle, square, cone, line) between lights and markers: `SceneLayerOrder.AoeTemplate = 35.5`; active when `activeLayer === MapLayerType.AoeTemplate`. Right-click (mouse) or a 500 ms single-finger hold (touch) on a shape fires `onAoeTemplateMenu(id, clientPosition, trigger)`; the editor opens `AoeTemplateContextPanel` for both, the TV (play page) opens its radial AoE menu for both and sets `aoeTemplates.playerSelectable` so shapes can be picked, dragged by their handles and edited while no tool is active. A mouse press that barely moves enters an `aiming` state (the next click places the shape); a touch tap discards the draft instead, and any draft is dropped when the layer stops being active. The TV does not auto-select a newly drawn shape, so toolbar swatches set the next shape's effect. Instead the just-drawn shape keeps its origin/end handles (`justDrawnId`, local to the layer) until a press misses them, so it can be moved, resized or rotated straight away; touch grabs handles at 2× the radius and the closest handle wins. With no tool active, a handle grab defers a tick and yields to a token claiming the same press. Sizes are in **feet**; `helpers/aoeTemplates.ts` (THREE-free, unit-tested) holds the SDFs, bounds, handle points and feet↔layer conversion.
- The fill shader follows the annotation rule: **effect is a compile-time `EFFECT_TYPE` define**, the program links via `compileAsync` before the material becomes visible, and all template materials share one `uTime` uniform object. Templates come in through `props.aoeTemplates` and go out through `onAoeTemplateAdded/Updated/Selected/Deleted`; the in-progress draft is local and cleared via `StageExports.aoeTemplates.cancelDraft()` (the consumer calls it on scene change).

- **Selection and labels**: a tap inside a shape selects it (`templateContainsPoint`) and repeated taps on a stack of overlapping shapes cycle through it (`nextTemplateInStack`); a tap on the only selected shape is still reported through `onAoeTemplatesSelected`, so the consumer can cycle a group; with the tool active a press that travels past the tap slop starts a NEW shape even on top of existing ones, and moving a shape is done by its origin handle (which carries every selected shape). Selection is multi: `props.selectedIds` (`selectedId` = last/primary), `onAoeTemplatesSelected(ids)`, and `StageExports.aoeTemplates.hitTest/inRectangle` take marker-space points so the editor's Shift-click/Shift-drag marquee can add shapes alongside tokens. With no tool active (`selectable`) the layer is select-only and yields to a marker click via `markerClaimAt`, like lights. New shapes rotate smoothly (`snapAngle` defaults off; squares only snap to 90° when it is on). Dimension text ("20 ft cone") shows only on a hand-drawn draft; an area with `AoeTemplate.spellId` never shows dimensions (`formatTemplateLabel`), its name follows `showLabels`, and selecting it draws a **label card** instead (canvas panel with a spell-colour accent bar, the name and `SpellDefinition.description`, one plain line without numbers; `AoeTemplateHandles` builds it once per text change under the same cache rule as the plain label). The draft outline is dashed at 0.4 opacity in the effect colour. Effects must animate from continuous `t` — never `floor(t * n)` — and the layer calls `framePacer.markAmbient()` while any effect is animating (see ambient pacing).
- **Anchored and expiring templates**: `AoeTemplate.anchorMarkerId` makes a template follow that token — the layer takes `markers` (`props.marker.markers`, mutated in place during a drag, so the live position is used mid-drag) and resolves positions with `withAnchoredPosition`; an anchored template has no origin handle and is skipped by group moves, and falls back to its stored position when the token is gone. The consumer persists the stored position on `onMarkersMoveEnd` (`anchoredTemplateMoves` / the web `writeAnchoredTemplateMoves`). `AoeTemplate.expiresAt` (epoch ms) fades the fill over the last `templateFadeMs(template)` (an instant spell's own `INSTANT_FADE_MS` = 3 s, else `EXPIRY_FADE_MS`; the web side sets an instant spell's `expiresAt` to cast start + cast duration + 3 s, so the blast holds full strength through the animation) through the per-material `uFade` uniform (a `useTask` that only runs for expiring templates) and a 1 s clock drops it from hit-testing afterwards; deleting the row is the consumer's sweep. `AoeEffect` values 18–28 (Thunder … SpikeGrowth) are the spell effects; radial effects use `shapeCenter()`/`shapeRadius()` in the shader. Spell catalog and rulesets live in `helpers/spells.ts` / `helpers/rulesets.ts` (THREE-free, exported from the package).
- **Spell aiming**: `AoeToolSettings.spell` (`SpellAimSettings`: `spellId`, `label`, `area` in feet, `effect`, `color`, `aim: 'point' | 'direction'`, optional `origin` + `originRadiusCells` (a fixed start at the caster's edge), `caster` + `rangeFt` (dashed range ring, `SpellRangeRing.svelte`)) turns the active AoE layer into an aiming surface: no free drawing, no handles, the preset shape and size are locked and the draft shows the spell's effect at draft opacity with its name and dimensions. `helpers/aoeTemplates.ts` holds the pure parts (`spellAimPlacement`, `spellAimDraft`, `spellRangeRadiusPx`, unit-tested): `point` centres cubes on the pointer; `direction` keeps the origin fixed (pushed out to the caster's edge along the aim angle) and lets the pointer set only the angle, or, without an origin, the first press sets it. Mouse: hover aims and a press places (a free direction aim takes two clicks); touch: press, drag, release places. Placement fires `Callbacks.onSpellAimed({ spellId, position, angle })` (layer-local px, the template's origin) instead of `onAoeTemplateAdded`. The layer owns no Escape/cancel: the **consumer** activates the AoE layer with `spell` set, restores its previous layer after `onSpellAimed` or on Escape/scene change/caster deletion, and must keep `spell` out of any persisted tool preferences (`withoutSessionAoeFields`). Leaving the layer or changing `spell.spellId` drops the half-aimed state. Self-centred spells never reach the stage (the consumer casts them at once).

## Spell cast FX

- `SpellCastLayer` (`components/SpellCastLayer/`, `SceneLayerOrder.SpellCast = 36.5`, `SceneLayer.Main` so bloom catches the HDR cores) is mounted in `anchoredLayers` right before `MarkerLayer`, so it shares the marker-space coordinates of `AoeTemplate.position`. Casts come through the `<Stage spellCasts>` interaction prop (copied into the `'stage'` context, kept out of `props`); the consumer prunes them after `durationMs` (`pruneSpellCasts`) and the layer renders only the newest `MAX_CONCURRENT_SPELL_CASTS` (6). `SpellCast.startedAt` is the local `performance.now()`.
- One program per archetype: `shaders/SpellCast.frag` selects `SPELL_FX` (`SPELL_FX_INDEX` in `helpers/spellCasts.ts`: burst, cone, bolt, wave, zone, aura, summon, rain; per-spell looks are each definition's `cast.variant` in `helpers/spells.ts` (`targeted`/`summon` take a `castVariant` option), e.g. zone 4 webbing / 5 billow / 6 void, beam 1 clamping chain links / 2 curse tendrils) at compile time; `variant`, `projectile`, tier and progress are uniforms. Same `compileAsync` gate as the AoE material (module-level ready/failed sets keyed by fx + composer, hidden until linked), materials pooled per archetype (`createSpellMaterialPool`), quad bounds and feet conversion from `getSpellCastBounds`. Output is premultiplied (`CustomBlending One/OneMinusSrcAlpha`), glow layers use alpha 0 with HDR rgb. Timeline: charge/travel 0-0.4, impact 0.4-0.6, settle 0.6-1. The SDFs are copied from `AoeTemplate.frag`; keep them in sync.
- `StageExports.spells.prewarm(castFxs?, tokenFxs?)` links programs ahead of a cast; apps/web calls it from `RadialMenu`'s `onSubmenuOpen` (TV and editor) with `spellFxToPrewarm(itemId, ...)`: a category ring or the Recent ring links only the cast archetypes and token effect kinds of the spells it shows, a summon links its own spell, the root and the group ring link nothing. Idle cost is zero: the layer's `useTask` runs only while casts exist, and meshes only exist per cast. A mesh calls `framePacer.markActive()` while it plays or waits for its program.
- **Lazy layers**: `Scene.svelte` does not import `SpellCastLayer` or `TokenEffectLayer` statically. It `import()`s each the first time something needs it (`stage.spellCasts` non-empty, `props.tokenEffects` non-empty, or a `prewarm` call), keeps it mounted afterwards, and replays prewarm requests made before the chunk arrived. Shader source (`?raw`) rides in the chunk; the `svelte-package` output keeps the dynamic imports. A cast whose program is not linked waits for `compileAsync` and starts its timeline then (`SpellCastMesh` shifts its local `startedAt`; `pruneSpellCasts` keeps casts `SPELL_CAST_LINK_GRACE_MS` past their duration for that).
- **Beam** is `SPELL_FX` 8 (caster to target ribbon, bloom on the token; bloom only without a caster); targeted and touch spells use it.

## Token effects

- `TokenEffectLayer` (`components/TokenEffectLayer/`, `shaders/TokenEffect.vert/.frag`) draws ambient effects bound to tokens from `StageProps.tokenEffects` (`TokenEffect`: `id`, `markerId`, `fx`, `color`, `radius` ft, `variant`, `startedAt` epoch ms). Kinds (`TOKEN_FX_INDEX`, append-only): orbit, glow, shimmer, ghosts, ward, chains, motes, haze, sigil, rift, charm and the internal `concentration` ring. One `InstancedMesh` per kind present (`TokenEffectKindMesh`), per-instance attributes `aTint` (rgb + seed), `aInfo` (start time, variant, half extent in token radii, orbit radius in token radii) and `aPx`; the kind is the compile-time `TOKEN_FX` define, materials are pooled per kind for the layer's lifetime, and the compile probe is an `InstancedMesh` so the linked program matches the drawn one. `helpers/tokenEffects.ts` (THREE-free, unit-tested) places effects from the live `props.marker.markers` (so they follow a token mid-drag, like anchored templates), drops effects of missing or viewer-hidden tokens, and builds the signature the instance buffers are rewritten on (never object identity).
- The shader works in token radii (`|q| = 1` is the token edge), so every kind scales with the token footprint. Ambient: the layer never calls `framePacer.markActive()`; `uTime` is quantised to 15 fps on the low tier and held at a fixed pose under `prefers-reduced-motion` (instances then start settled). Render order: `TokenEffectUnder = 36.8` for glow/orbit/haze/shimmer/ghosts/motes, `TokenEffectOver = 37.3` for chains/sigil/charm/rift/ward and the **concentration seal** (a scalloped wax-seal rosette, `r - (R + A cos(14 theta))`, drawn solid in the spell colour only outside |q| ≥ 0.97 so it frames the token without covering its art; the old thin additive ring vanished on pale maps). Chains reach ground stakes beyond the token (`tokenFxExtent('chains')` 2.8; variant 1 = four stakes). Kinds 12–23 (append-only `TOKEN_FX_INDEX`; 18–23 are the area-pick spells' looks, all vnoise-only with loop counts cut on the low tier: `calm` Calm emotions ripples and a breathing glow, `heal` Mass cure wounds green burst ring then rising sparkles (reads `uTime - start` so the burst plays once), `trance` Hypnotic pattern multicolour spiral, `outline` Faerie fire flickering rim glow that never covers the art, `dread` Fear dark claws creeping in with a shiver, `slumber` Sleep drifting Zs over a dim haze; `outline`, `dread` and `slumber` draw over the token, the rest under it): `clock` (Slow, over), `streaks` (Haste), `halo` (variant 0 Aid sunburst + crosses, variant 1 Heroism flames), `veil` (Invisibility, over: mist that makes the token see-through), `wind` (Fly: offset drop shadow + gusts), `blind` (Blindness/deafness, over: rim smoke + struck-through eye). Visually verify with a headless WebGL2 harness that supplies the instance attributes as constant vertex attributes.
- **Targeted aiming**: `SpellAimSettings.mode: 'target'` makes the AoE layer outline (via the context's `spellTargetMarkerId`, shown like a drop target) the visible token under the pointer that is in range (`helpers/spellTargets.ts`: edge-to-edge range from the caster, ring radius `rangeFt` + caster radius) and fire `Callbacks.onSpellTargeted({ spellId, markerId })` on a click or a touch release; the aim stays until the consumer ends it (consumers toggle picks and confirm; there is no per-spell target cap). Picked tokens come back as `SpellAimSettings.pickedMarkerIds`, which the AoE layer copies into the context's `spellPickedMarkerIds` so MarkerLayer draws them as selected. A tap on empty map does nothing; right-click fires `onSpellAimCancelled`. **Area-pick aiming**: `mode: 'area-targets'` aims exactly like an area spell until the commit, which fires `Callbacks.onSpellAreaTargets({ spellId, placement, markerIds })` instead of `onSpellAimed`. The `placement` is consumer-owned (`SpellAimSettings.placement`): once it is set the layer draws the placed draft from props, derives the inside set (`markersInSpellArea` in `helpers/spellTargets.ts`: bounding-box early out in the template frame, then `templateSdf(centre) < tokenRadiusFt - AREA_OVERLAP_TOLERANCE_FT` on the drawn 90% circle, visible tokens only, one pass, allocation-free but the result) as a `$derived` of placement + markers + viewer, and reports again only when the placement or the id list differs from the last report (`sameMarkerIds`, never per frame; the consumer's echo of its own placement changes nothing). Gestures once placed: press records a candidate (the inside token under the press, plus the grab offset); release without crossing the slop (3 px mouse, 8 px touch) on an inside token fires `onSpellTargeted` (toggle); crossing it drags the area (point aim keeps the grab offset and snaps; direction aim with a fixed origin re-aims the angle), reporting each move. The inside tokens go to the context's `spellEligibleMarkerIds` (MarkerLayer draws them hovered) and `pickedMarkerIds` as selected. Touch end may carry null coords (cancel): that drops the press without a toggle. `AoeTemplate.effectOnly` rows (effect-only spells) are skipped by the AoE layer (no fill, hit-test or handles) but still listed by the editor.
- Tiers: high adds a trail and up to 6 px / 180 ms camera shake on blast impacts (the layer writes `cameraShake`, a plain object in context `'cameraShake'`; Scene's render task offsets `camera.position` around both passes and restores it); medium has neither; low skips travel (progress starts at 0.4, duration x0.6). Reduced motion = the consumer passes a lower tier.
- Ephemeral sync lives in apps/web `PresenceChannel.castSpell` + `receiveSpellCast` (awareness field `spellCast`, new id per remote client, same scene only, field cleared after the duration). Visually verify shader changes with a headless WebGL2 harness: compile every `SPELL_FX` value and render contact sheets of progress steps.

## Distances, token toggle and player AoE

- `helpers/moveDistance.ts` (THREE-free, tested) counts grid steps with diagonals = 1 and multiplies by `grid.worldGridSize`. `DistanceLabel` is the shared constant-screen-size label sprite; MarkerLayer shows it for the live "ft moved" while a token (or group anchor) is dragged, and — when the `<Stage distanceMode>` interaction prop is on — from the selected token to every other visible token.
- `<Stage onMarkerVisibilityToggle>` mounts `MarkerVisibilityToggle` (HTML eye button) above the single selected token in DM mode on the None/Marker layers.
- AoE input is no longer DM-only: players can draw with the tool active (`selectable` passive selection stays DM-only), and group drag works in Player mode. Player shapes are written to the doc by `play/usePlayTools.svelte.ts`. The TV edits assets only (tokens, shapes, conditions, groups, measuring, drawings saved per stroke as player annotation layers; no fog/scene/map edits) and has its own undo scope; the editor's undo uses `setUndoScope(sceneId, { includeRemote: true })` so the GM can undo TV edits (see `docs/undo-redo-architecture.md`). With shapes selected, the effect picker (TV swatches and the GM toolbar) recolors only the selection and leaves the tool's effect for the next shape alone.

## Radial menu (TV)

Full design: `docs/tv-radial-menu-architecture.md`.

- `RadialMenu` (`components/RadialMenu/`) is the TV's only menu. It keeps a stack of submenu ids and re-reads each level from `items`, so options that change while it is open (a condition toggled on) update in place. The hub and any tap outside the ring go back one level and close at the top level; the menu ignores clicks that did not start on it (the long press that opened it ends over it). Items take `label` (always shown), `hint` (shown in the hub while pressed or hovered), `accent`, `active`, `badge`, `danger`, `disabled` (still pressable so the hub can explain), `keepOpen` and `submenu`; the ring radius grows with the option count and everything rotates to face the nearest screen edge.
- `onMarkerLongPress(marker, clientPoint)` fires after a 500 ms still press on a token (12 px slop) only when a consumer registers it (the editor doesn't). It cancels the pending drag and suppresses the release click, so a long press never moves or re-selects the token. Shapes report long press through `onAoeTemplateMenu`; the play page detects long press on empty map itself.

## Editor selection and player handouts

Token groups are local editor state, separate from the edited token. Desktop Shift drag selects token centers; Ctrl drag pans the entire viewport through PointerInputManager alone. Use differences in client coordinates for pointer deltas; do not also apply panning in the editor mousemove tracker, which tracks cursor/clipboard targeting only. Touch selection uses the existing styled `InputCheckbox` in the token sidebar, plus select-all/clear controls. Mobile token controls use the outer editor tools scroller, with natural content height and a non-sticky token header, so short vertical panes cannot collapse or obscure the list.

Player handouts are application overlays above Stage, rendering original artwork with contain sizing. They consume pointer targeting and do not globally dismiss on Escape. Pause suppresses presentation while retaining party state. Party-wide viewer connections are read-only; game-session connections and visible, unpinned player token movement remain writable. See `docs/yjs-sync-architecture.md`.
