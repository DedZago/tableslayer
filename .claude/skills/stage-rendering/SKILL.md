# @tableslayer/stage rendering architecture

> **Freshness**: last verified 2026-10-18 (Threlte 8.6, Three 0.186, postprocessing 6.39).
> Anchor files at the bottom — if one is missing/renamed, the code wins; update this skill.
> Deeper current docs: `docs/grid-system-architecture.md` (grid math), `docs/stage-performance-guide.md` (perf workflow).

## Big picture

- `Stage.svelte` (`packages/stage/src/lib/components/Stage/components/Stage/Stage.svelte`) is the public entry: creates a custom `WebGLRenderer` (`antialias: false` — everything is textured quads AA'd in-texture; MSAA would be wasted), renders `<Canvas renderMode="always">` (continuous loop — animated shaders/weather need it), and mounts `Scene.svelte`.
- **Idle frame pacing** (`helpers/framePacing.ts`): the loop always ticks (tasks run, `uTime` advances), but Scene's render task skips GPU work while idle — `IDLE_FRAME_RATE` per tier (`high: null` = uncapped, medium 30, low 20). Skipping a frame without GL calls keeps the previous image on the canvas. Scene puts the pacer in context `'framePacer'`; anything that marks activity gets full rate for `ACTIVE_WINDOW_MS`: props-root/cursors/measurement changes, window pointer/wheel/key input, map load, resize. A layer with a transient animation that must stay smooth calls `getContext<FramePacer>('framePacer')?.markActive()` from its task (MeasurementManager fade, CursorLayer while cursors exist). Async texture updates while idle appear on the next idle frame (≤ 50 ms).
- `Scene.svelte` is the heart: single `T.OrthographicCamera`; **pan/zoom is applied to a wrapping `T.Object3D` (`props.scene.offset`/`zoom`), not the camera**. Inside it, a **`mapAnchor` node always carries the uniform map transform** (`position = map.offset`, `rotation = map.rotation`, `scale = map.zoom`); `MapLayer`'s inner node only scales the unit plane to the image size.
- **MapDefined anchoring**: grid/annotation/light/marker/measurement layers live in an `anchoredLayers` snippet mounted **inside `mapAnchor`** when `gridMode === MapDefined` (and `mapSize` is loaded) and at scene level in FillSpace. Anchored layers receive a **synthetic map-space `DisplayProps`** (`anchoredDisplay` via `getMapSpaceDisplay`: resolution = mapSize px, size = fixedGridCount × spacing "inches") so all their display-space math computes in map pixels unchanged, plus `localScale` (= map.zoom) to convert screen-px style values to local px. Marker/light positions are center-relative **map pixels** in MapDefined, display pixels in FillSpace; conversion contract lives in `helpers/mapSpace.ts` (THREE-free, exported — apps/web shares it).
- Two distinct "layer" enums in `Scene/types.ts` — do not confuse them:
  - `SceneLayerOrder` — Three.js `renderOrder` (Background 0 → Map 10 → Fog 20 → … → Grid 50 → … → TvViewport 95 → Cursor 100).
  - `SceneLayer` — Three.js camera-layer masks: `Main = 0` (gets postprocessing), `Overlay = 1` (grid/measurement/cursor — deliberately skips bloom/LUT), `Input = 2` (invisible raycast targets).
- **Two-pass render loop** (custom `useTask` in Scene.svelte; Threlte `autoRender` is disabled, `renderer.autoClear = false`): pass 1 renders `Main` through the `postprocessing` EffectComposer (Bloom, ChromaticAberration, Vignette, LUT3D, ToneMapping); pass 2 renders `Overlay` directly. If all effects are zero-strength (`getActiveEffects`), the composer is **bypassed entirely** — a key perf path. The composer is disposed and rebuilt whenever `props.postProcessing` changes.
- Offscreen targets: WeatherLayer renders particles into its own `WebGLRenderTarget`; `DrawingMaterial` (fog-of-war + annotation painting) uses **double-buffered ping-pong render targets**; `generateThumbnail` swaps a temp scene/camera into the composer and reads back via `OffscreenCanvas`.
- **Mask readback is async and lazy.** `DrawingMaterial.toPng/toRLE` use `renderer.readRenderTargetPixelsAsync` (three issues `readPixels` into a PBO before its first await, so the snapshot is taken at call time; callers re-check `isDrawing()` after awaiting). `onFogUpdate(getBlob)` / `onAnnotationUpdate(layerId, getBlob, pos)` receive a **thunk** — call it only if you need the PNG; never pass an eager `toPng()` (that was a full-res readback + PNG encode per stroke the editor discarded). RLE encode/decode live in `@tableslayer/ui` `utils/rle.ts`; output format is persisted, so changes must stay byte-identical (`rle.test.ts` pins it against the legacy encoder).
- **Map images decode off the main thread**: `ImageDataSource` uses `fetch` + `createImageBitmap({ imageOrientation: 'flipY', colorSpaceConversion: 'default' })` with `texture.flipY = false` (WebGL ignores UNPACK_FLIP_Y for ImageBitmap; three's `ImageBitmapLoader` is avoided because it forces `colorSpaceConversion: 'none'`). `dispose()` closes the bitmap, so detach `material.map` before disposing a source whose mesh stays mounted. Falls back to `TextureLoader` without `createImageBitmap`.
- **Fog.frag**: the feathered mask (mip loop) and base mask are computed once in `main()` and passed to the per-layer `mask()`; only the edge noise is per-layer. Don't move texture work back into per-layer functions.
- **Polygon fog rooms** (`props.fogOfWar.rooms`, `helpers/fogRooms.ts` — THREE-free, shared with apps/web): committed rooms + the in-progress draft are rasterized into a map-sized `CanvasTexture` in `FogOfWarMaterial` — enabled rooms in the GREEN channel, toggled-off rooms in RED — and composited in `Fog.frag` as `max(enabled, base * (1 - disabled))`: erase strokes never cut into enabled rooms, a toggled-off room actively reveals its interior through the base mask, and an enclosing enabled room still wins (nesting). Room points are normalized [0-1] mask-UV (v up; canvas draws at `(1-v)*h`, CanvasTexture flipY un-flips). Data out via `Callbacks.onFogRoomAdd/onFogRoomToggle/onFogRoomDelete` (hit-tests pick the smallest containing room, enabled or not); commit via Enter (consumer's job through `StageExports.fogOfWar.commitPolygon/cancelPolygon/polygonPointCount`), double-click/double-tap, or clicking the first vertex. Toggle = right-click or touch double-tap with ANY tool/layer active, in DM mode AND on the Player-mode playfield (`LayerInput.isContextMenuActive` bypasses the isActive gate for contextmenu; `LayerInput.onDoubleTap` is an always-on touch detector). Marker precedence: consumers defer the right-click toggle one tick so a marker context menu wins; on touch, MarkerLayer stamps `stageContext.markerClaimAt` on marker-hitting pointer-downs and the fog layer's double-tap defers 120ms and yields to recent claims. Delete = Delete/Backspace while hovering (`deleteRoomAtCursor`) or touch press-and-hold — both polygon-tool-gated, so effectively editor-only (Shift+right-click also works, but Firefox forces its native menu on Shift+right-click regardless of preventDefault — never make that the only path). stageKeyCommands' Shift-deselect exempts the polygon tool (it ignores Shift/Ctrl-modified clicks itself). Preview/outlines are triangle ribbons + disc vertices (`FogRoomLine/Disc` shaders, fwidth-feathered — LineBasicMaterial linewidth is unsupported) built at constant ON-SCREEN thickness by dividing by `mapZoom * sceneZoom` (a fixed texture-px width goes sub-pixel and aliases when zoomed out); the cursor acts as the provisional last vertex so the draft always reads as a closed polygon. The draft deliberately survives `isActive` toggles (Ctrl pan) and resets on tool/map change.

## Props and control flow

- One flat `StageProps` object (`Stage/components/Stage/types.ts`) with a sub-object per layer, passed down whole; layers take their slice.
- **The stage never mutates props.** Data flows out through the `Callbacks` interface (`onSceneUpdate`, `onFogUpdate`, marker/light/measurement callbacks), provided via `setContext('callbacks', …)`; the parent writes new values back into its `$state` stageProps. Pan/zoom round-trips through this loop.
- Imperative API: `StageExports` — parent does `bind:this={stage}` and calls e.g. `stage.fogOfWar.toRLE()`. These delegate Stage → Scene → layer → material with `?.` at every hop.
- `stageContext` (context `'stage'`) carries reactive `mode`, `performanceTier`, hovered/pinned marker ids.
- Input (pan/zoom/rotate gestures, wheel, keyboard) is the **parent's** job via the exported `PointerInputManager` — Stage itself doesn't bind wheel/keys.

## Shaders

- GLSL lives in `packages/stage/src/lib/components/Stage/shaders/*.frag|.vert`, imported as strings with Vite `?raw`. Exception: the light shader is inline TS (`LightLayer/lightShader.ts`, uses `#include <clipping_planes_*>`). `AnnotationEffects.frag` is the 1400-line monster (Fire/Water/Magic/etc. effects) — but **the effect is a compile-time `EFFECT_TYPE` define** (`AnnotationMaterial` sets `defines.EFFECT_TYPE`, each effect's functions sit in `#if EFFECT_TYPE == n` blocks, `main()` dispatches with `#if/#elif`), so a program only contains its own effect. Never move effect selection back into a uniform: the all-in-one program took ~90 s to link on Windows, where both Chrome and Firefox run WebGL through ANGLE → D3D11 → the FXC HLSL compiler, which inlines/unrolls everything (Chrome's GPU watchdog then killed the process → context-loss loop). Same rule for any new big shader: branch on defines, keep loop bounds literal.
- **Shader precompile**: `AnnotationMaterial` links its program via `renderer.compileAsync` (`KHR_parallel_shader_compile`) with `material.visible = false` until ready, so a slow link never stalls the frame loop. three keys programs on (among other things) `renderer.clippingPlanes.length`, the defines, and whether the output is a render target (`outputColorSpace` param) — so the probe compile binds a 1×1 render target when the layer will render through the composer (`stageContext.mainPassUsesComposer`, computed by `helpers/postProcessing.ts`). If a material still links twice, diff the two program sources (`#define` prefix) — that's how the target/plane-count keys were found. The F9 perf overlay shows `Programs` (`renderer.info.programs.length`) to spot thrash. `EffectPreviewScene` (radial menu / DrawingSliders effect thumbnails) is one Threlte `<Canvas>` = one WebGL context per preview: it uses the same `compileAsync` gate and **releases its context on unmount** (`WEBGL_lose_context.loseContext()` after Threlte's dispose) — browsers cap live contexts (Chrome 16) and evict the oldest, i.e. the stage.
- Uniform idiom: create uniforms once at material construction; update in `$effect` with **in-place mutation** (`uniforms.uColor.value.set(...)`, `.copy(...)`) — never allocate new objects per frame. Time-driven uniforms advance in `useTask((delta) => { uniforms.uTime.value += delta })`. Dispose materials in `onDestroy`.
- The JS grid-snapping math in `helpers/grid.ts` is a **hand-ported mirror of the shader's `getHex`** (and compensates for the shader's `lineThickness/4.0` visual offset). If you change `GridShader.frag` grid math, change `helpers/grid.ts` to match, and vice versa.

## Gotchas (the expensive ones)

- **`$state.raw()` for Three objects** (`$state.raw(new THREE.Mesh())`) — Svelte 5 proxies break Three's internals. Recurring pattern in FogOfWarLayer, WeatherLayer.
- **Y-flips everywhere**: render-target readback is vertically flipped — `toPng` un-flips via canvas transform; `toRLE`/`fromRLE` flip rows manually (`height-1-y`) and pack **alpha channel only**. NDC→pixel conversions flip y (`-v.y*0.5+0.5`). The weather particle camera is intentionally upside-down (`rotation.x = Math.PI`).
- **Brush sizes are in grid units**, converted to texture pixels via `getGridCellSize` (fog additionally divides by map zoom; annotation uses the synthetic map-space display in MapDefined — the two formulas agree under the locked zoom), then **halved** (shaders treat `uBrushSize` as a radius).
- **Resize must happen in the render task, not `$effect`** — `needsResize` flag pattern in Scene.svelte; the size-mismatch check doesn't work in effects.
- **Effects must key off prop VALUES, not sub-object identity.** apps/web replaces the whole stageProps ROOT on every remote doc change — structural sharing preserves identity for unchanged subtrees, but any effect whose dependency chain reaches the root signal still re-fires per received update. Template-expression props (`strokeColor={props.marker.shape.strokeColor}`) carry the root in their chain, so a child effect reading such a prop directly re-runs per remote pan step even though the value never changed. Only `$derived` cuts the chain (it re-propagates only when its VALUE changes). Three past incidents: setSize + autoFit refit per update (Scene.svelte `resizedForMapUrl` guard), full EffectComposer rebuild per update (`lastPostProcessingKey` guard), and per-marker canvas redraw + gaussian shadow blur + texture upload per update (~30ms/marker; MarkerToken routes every style prop through `$derived`). When adding an expensive effect, route each input through `$derived` or a last-value comparison.
- DPR is capped by `props.display.maxPixelRatio` (default 2) for weak GPUs.
- **Performance tiers**: `PerformanceTier = 'high'|'medium'|'low'` with the knob table `PERFORMANCE_TIER_SETTINGS` in `Stage/components/Stage/types.ts` (fog layer count/octave cap, weather resolution+particle scale, `forcePostProcessingOff` on low). The consumer picks the tier — Stage never auto-detects. Shaders also receive `uPerformanceTier`. Tier changes apply live.
- **Clipping planes**: two stores in `helpers/clippingPlaneStore.svelte.ts` — display bounds (on the renderer) vs map bounds (on weather/light materials so effects stop at map edges). **Never set `renderer.clippingPlanes = []`** — always four planes (`noClipPlanes()` pushes them to ±1e9): three substitutes the count into `NUM_CLIPPING_PLANES` and keys the program cache on it, so `[]` would relink every material and give shaders a zero-length `uClippingPlanes[]`. `Stage.svelte` sets the four planes at renderer creation; `generateThumbnail` and `annotationSpaceConversion` use `noClipPlanes()`. In **DM + MapDefined** the display-bounds store is "disabled" the same way so the whole map is visible; `TvViewportLayer` draws the playfield rectangle + dim mask instead. Player mode keeps clipping.
- **MapDefined grid cells are always square**: the quad IS the map; the synthetic map-space display has uniform pixel pitch, so `gridSpacing = uSpacing_in/pixelPitch` yields the per-axis-average square cell and the grid is centered on the map (count/aspect mismatch = edge misfit, not rectangles). Mirrored in `helpers/grid.ts` (`getGridOrigin` centers; `snapToGrid` takes an optional `localScale` for the `t/4` offset compensation). The count describes the map image (X along the image's width, like the `name_WxH` filename convention) and is invariant under rotation. Grid lines are analytically AA'd inside `squareGrid`/`hexGrid` via `fwidth()` with the half-width floored at one device pixel — sub-pixel hard bands alias into patchy moiré/phase-dependent brightness.
- **Legacy annotation conversion**: persisted RLE masks embed 8-byte width/height; in MapDefined, a mask at the real display resolution is legacy display-space data and gets GPU re-projected into the map-sized texture (`helpers/annotationSpaceConversion.ts` + `AnnotationMaterial`'s `conversion` prop), then persisted once via the normal `onAnnotationUpdate` flow.
- `scene.fit()` in DM + MapDefined frames the map ∪ TV rect (5% margin) instead of the display bounds; `getMarkerScreenPosition`/`getMarkerSizeInScreenSpace` apply the map transform in MapDefined.
- MapLayer disposes the old data source and `material.map` before loading a new one; video URLs keep query params (cache-busting) while image URLs strip them. Data sources are pluggable (`MapLayer/dataSources/` — Image, Video, Gif — each with `.dispose()`).
- Desktop Ctrl-drag pans the whole scene (map, grid and tokens together). Shift-drag is reserved for editor token selection, and never pans the map. LayerInput yields Ctrl/Meta mouse-downs to view controls. Touch map/scene gestures remain separate.
- `marker.selectedIds` and `marker.dropTargetId` are optional local selection/drop presentation state; consumers must keep it out of shared documents. `markers.hitTest` and `markers.inRectangle` accept viewport client coordinates, project through the current map and scene transforms, and exclude non-interactable tokens. The editor captures Shift mouse gestures before layer handlers; Shift-click toggles and Shift-drag adds token centers in the rectangle.
- `markers.clientToPosition(point, requireOnMap)` inverts the live orthographic camera, scene offset/zoom and (in MapDefined) map offset/rotation/zoom. `markers.viewportCenter()` supplies a paste fallback; `markers.snapPosition()` applies the renderer's grid math once to the group anchor. Public `getGridCellSize` and `snapToGrid` exports let consumers reuse existing grid calculations.
- Touch input debounces 50ms to disambiguate draw vs pinch-zoom (`LayerInput.svelte`).
- Lights are selectable and draggable in both the Light tool and the no-tool state (`LightLayer` is active for `None` too); in `None` a light click defers one tick and yields to a marker claim (`markerClaimAt`). The editor's Delete/Backspace removes selected tokens or the selected light.
- Annotation layers with visual effects render on `SceneLayer.Main` (get postprocessing); plain-color layers render on `Overlay`.

## Tokens, selection and combat state

- **Selection is not in props.** Consumers pass `selectedMarkerIds`, `dropTargetMarkerId` and `activeTurnMarkerId` as `<Stage>` component props (`StageInteractionProps`); `Stage.svelte` copies them into the `'stage'` context, and MarkerLayer reads them from there. Keeping them out of the `props` root means a click does not invalidate every effect chained to `props` (see the effects gotcha above). `marker.selectedIds`/`dropTargetId` remain as a fallback.
- **Token raster never encodes selection, hover or turn state.** `MarkerToken` draws image/shape/label into a 512px `CanvasTexture` that is reused across redraws and recreated only when the raster size changes, since three allocates immutable GPU storage on first upload (design space stays 1024 via `setTransform`; shadow blur is scaled by hand). Selection, hover and active-turn are separate ring meshes with shared materials (`helpers/tokenRasterCache.ts`: shared quad geometry, `ImageBitmap` LRU (128 URLs, evicted bitmaps are dropped, never `close()`d — a token may be about to draw it) via `loadTokenImage`, CSS colour cache invalidated by a theme `MutationObserver`; colours are normalised to `rgb()` through a 1px canvas because `THREE.Color` can't parse the oklch theme tokens). The active-turn pulse is one `useTask` with `running: () => isActiveTurn` (a `useTask` cannot sit inside `{#if}`).
- **Drag threshold**: a press becomes a drag only after 3px (mouse) / 8px (touch); a stationary click never calls `onMarkerMoved`. Pressing a token that belongs to a ≥2 selection starts a group drag that reports through `onMarkersMoved(moves)` (falls back to per-marker `onMarkerMoved`); the gesture end (mouseup, window blur, layer reset/unmount) fires `onMarkersMoveEnd({ ids, cancelled })` — consumers close their undo group there, never on an idle timer. Escape mid-drag restores start positions, calls `preventDefault` and reports `cancelled: true`. While a press is still below the threshold, `markerState.tooltipSuppressed` is true so the player tooltip doesn't flash.
- **Conditions**: `Marker.conditions` (`MarkerCondition { id, label?, color?, value?, dmOnly? }`). Catalog and pure helpers live in `helpers/markerConditions.ts` (`MARKER_CONDITIONS`, `MARKER_CONDITION_ORDER`, `resolveCondition`, `toggleCondition`, `sortConditions`), exported for apps/web. `MarkerConditionBadges` renders inside the token's scaled group; `dead` dims the token and overlays a skull. Consumers filter `dmOnly` conditions out of player props.

## AoE templates

- `AoeTemplateLayer` (`components/AoeTemplateLayer/`) renders spell templates (circle, square, cone, line) between lights and markers: `SceneLayerOrder.AoeTemplate = 35.5`; active when `activeLayer === MapLayerType.AoeTemplate`. Sizes are in **feet**; `helpers/aoeTemplates.ts` (THREE-free, unit-tested) holds the SDFs, bounds, handle points and feet↔layer conversion.
- The fill shader follows the annotation rule: **effect is a compile-time `EFFECT_TYPE` define**, the program links via `compileAsync` before the material becomes visible, and all template materials share one `uTime` uniform object. Templates come in through `props.aoeTemplates` and go out through `onAoeTemplateAdded/Updated/Selected/Deleted`; the in-progress draft is local and cleared via `StageExports.aoeTemplates.cancelDraft()` (the consumer calls it on scene change).

## Editor selection and player handouts

Token groups are local editor state, separate from the edited token. Desktop Shift drag selects token centers; Ctrl drag pans the entire viewport through PointerInputManager alone. Use differences in client coordinates for pointer deltas; do not also apply panning in the editor mousemove tracker, which tracks cursor/clipboard targeting only. Touch selection uses the existing styled `InputCheckbox` in the token sidebar, plus select-all/clear controls. Mobile token controls use the outer editor tools scroller, with natural content height and a non-sticky token header, so short vertical panes cannot collapse or obscure the list.

Player handouts are application overlays above Stage, rendering original artwork with contain sizing. They consume pointer targeting and do not globally dismiss on Escape. Pause suppresses presentation while retaining party state. Party-wide viewer connections are read-only; game-session connections and visible, unpinned player token movement remain writable. See `docs/yjs-sync-architecture.md`.
